# C施工计划：配置、控制与二维工作台

你和你的agent直接按本页与[统一施工契约](contracts.md)实施，无须让A/B先定义页面字段。对应主计划F01/F02/F03/F05及第4节、W2产品交付。后端端点、DTO、Mock状态和反馈规则已由负责人固定。

## 1. 你的交付结果

1. 增加模板配置页：读取固定campus-w2模板，编辑实验名称、8角色简介/兴趣/目标/起点和简化日程，保存后采用服务端返回的规范化ID；展示字段错误。无地图编辑器，无角色增删。
2. 接通实验列表/详情、保存和新建运行。创建ID为一次操作生成并复用，响应丢失重试不产生两个运行；新运行使用自己的不可变配置快照。页面完成DRAFT校验、READY启动，不再依赖手工seed作为唯一入口。
3. 补齐启动/暂停/继续/停止控制。按钮按权威状态启用，停止有一次确认；普通迁移先显示已接收，匹配本命令事件后生效；固定No-op显示“已是目标状态”，不等待不存在的事件。
4. 展示5地点、固定路线和8角色，地图/列表可选择角色，显示位置、动作、当前目标、规则摘要和原有观察记忆。新旧运行使用各自的配置，不把旧操场替换成宿舍。
5. 按动作segments与仿真时间做显示插值；暂停/终态/断线停止外推。刷新和重连先同步状态，事件按连续seq补齐，切换运行隔离缓存和未完成请求。
6. 提供规则任务/故障摘要和恢复原因；执行2名非开发同学的流程走查及真实浏览器验收。保留原通知、事件与记忆流程。

## 2. 架构与文件归属

使用**Facade + 读取/提交分工**：HTTP转发请求，A的应用服务负责配置与运行写入；运行控制统一走CommandInbox/CommandProcessor。你不能在路由中直接更新Run、角色、时间或动作。

你负责`api/workbench.py`及新增配置路由、`application/workbench.py`等公开DTO/读取端口、`infrastructure/postgres/workbench.py`等只读查询，以及整个`frontend/`。A拥有写服务/核心仓储；B拥有bootstrap、API lifespan和Worker装配，你导出自己的路由/读取工厂供B接入，不并行编辑装配文件。

状态查询维持运行共享锁，世界部分的seq、时钟、位置与动作来自一致视图。B的任务摘要是附加只读信息，不能用它推断人物已经移动。前端不提交坐标、不做世界时钟、不产生逐帧事件。

## 3. 直接采用的接口与页面规则

契约第3节给出全部端点和请求；第8节给出RunView/AgentView扩展；第9节提供固定Mock。直接制作DRAFT、READY、RUNNING移动中、PAUSED、FINISHED、No-op、拒绝、409和断线数据开始开发，不等待真实后端。

MOVE显示使用各段duration_ms定位当前段，再沿path长度插值；1×只是显示外推参数，后端sim_time始终权威。陈宇演示时段为5000—15000毫秒，暂停快照9000毫秒任意墙钟等待后保持不变。

ResumeRun的正常生效事件是RunResumed；若恢复的是尚未启动过的运行，按固定恢复例外匹配RunStarted。恢复后无效配置会被拒绝，页面展示原因，不能绕过后端强行改状态。

客户端只为一次创建生成experiment_id/run_id，只为一次命令生成request_id，并在不确定响应后复用原内容。角色ID由服务端规范化返回，姓名不是主键。旧运行缺扩展字段时显示静态地图和旧演示标识，不擅自改快照。

## 4. 验收与交付

第1日完成Mock、配置与控制骨架；第2—3日完成地图、DTO/路由与状态同步；第4日切换真实服务；第5日走查、修复并记录结果。

必须让用户无需命令行完成配置、新建、校验、启动、观察移动、暂停、继续和停止；暂停时坐标及时间冻结；重复点击、No-op、响应丢失、刷新、断线及切换运行不出现重复执行或串数据；停止后显示最终位置；通知仍按精确causation_id确认生效。

交付前端逻辑测试、类型检查/构建、API请求响应测试、浏览器完整流程、2人走查和`docs/stage4-w2/acceptance-C.md`。截图与记录说明是否来自真实服务；Mock通过不代替联调通过。不实现模型设置、回放、指标导出或复杂美术。
